# 紅石發票列印代理（本地代理，跑在櫃檯電腦）

驅動 WinPOS WP-560 二聯式發票機的小程式。跑在**每一台有接發票機的櫃檯電腦**上，
開一個 `http://localhost:3399`，供員工端網頁（`staff.redrocktaiwan.com`）呼叫來實際印票。

完整背景/決策見 `../docs/invoice-integration-plan.md`（第 3、5.1、5.5 節）。

## 安裝（Windows 櫃檯電腦，值班人員可獨立完成）

> 💡 以下步驟**大部分不需要系統管理員（admin）權限**，只有「插新硬體第一次要裝驅動程式」這一步有可能需要——遇到才需要找 admin，其餘都可以自己做。詳見下方「如果卡住了」。

### 第一步：確認硬體
1. 把 USB 轉 RS-232 轉接線插上電腦、另一端接發票機，發票機開機。
2. 開始選單搜尋「**裝置管理員**」打開，展開「**連接埠 (COM 與 LPT)**」這一項。
3. 應該會看到一個類似「`USB-SERIAL CH340 (COM3)`」的項目——**記下 `COM` 後面的數字**（例如 `COM3`），等一下會用到。
   - ⚠️ **如果完全沒看到新的項目**（裝置管理員裡找不到任何 COM 埠），代表這台電腦沒裝過這條線的驅動程式，這步需要 admin 權限才能裝，請找有權限的人協助裝好驅動、裝完之後這個項目就會出現，之後就不需要 admin 了，可以接著往下做。

### 第二步：安裝 Node.js（免安裝版，不需要 admin）
1. 到 <https://nodejs.org/en/download> 下載「**Windows Binary (.zip)**」版本（不是安裝檔 `.msi`，是壓縮檔）。
2. 解壓縮，裡面會有一個資料夾（打開後應該看得到 `node.exe`）。把這整個資料夾**改名為 `nodejs-portable`**。
3. 把 `nodejs-portable` 這個資料夾，搬到跟 `install.bat`（這個資料夾裡）**同一層**。

   > 如果這台電腦剛好已經裝過 Node.js（一般安裝版），這步可以跳過，下面的腳本會自動偵測並使用已安裝的版本。

### 第三步：安裝並啟動
1. 雙擊這個資料夾裡的 **`install.bat`**，跟著畫面上的提示等它跑完（第一次要一兩分鐘）。
2. 跑完後，用記事本打開資料夾裡新出現的 **`.env`** 檔案，找到 `SERIAL_PORT` 這一行，把後面的值改成第一步查到的 COM 埠（例如改成 `SERIAL_PORT=COM3`），存檔關閉。
3. 雙擊 **`start.bat`**，看到「`✅ 發票列印代理已啟動：http://localhost:3399`」就是成功了。**這個黑色視窗要保持開著**（可以縮小，但不要關閉，關掉列印功能就會停止）。
4. 打開瀏覽器輸入 `http://localhost:3399`，會看到內建測試頁，按「🖨️ 測試列印」印一張確認機器有反應。

### 第四步：設定開機自動啟動（兩種做法，擇一）

**做法 A：不需要 admin（簡易版，會有黑色視窗）**
1. 按 `Win + R`，輸入 `shell:startup`，按 Enter，會打開一個「啟動」資料夾。
2. 回到 `start.bat` 所在資料夾，在 `start.bat` 上按右鍵 →「傳送到」→「桌面（建立捷徑）」。
3. 把桌面上新出現的「start.bat 的捷徑」，剪下貼到剛剛打開的「啟動」資料夾裡。
4. 之後這台電腦每次開機、這個帳號登入後，代理就會自動啟動（會跳出黑色視窗，屬正常現象，不要關掉；**如果視窗被誤按 X 關掉，代理就停了，不會自己重開**，需要重新雙擊 `start.bat`）。

**做法 B：裝成 Windows 背景服務（需要 admin，較穩，開機不用登入、沒有黑色視窗、被關掉/當機會自動重開）**
1. 在開始選單找到「命令提示字元」或「PowerShell」，**右鍵 →「以系統管理員身分執行」**。
2. `cd` 到這個資料夾（例如 `cd C:\redrock\local-print-agent`）。
3. 如果還沒裝過依賴，先跑一次 `npm install`。
4. 執行：
   ```
   npm run install-service
   ```
5. 看到「✅ 服務已啟動，之後開機會自動在背景執行」就完成了——**不會再看到黑色視窗**，代理已經在背景默默跑著。
6. 確認方式：開始選單搜尋「**服務**」（Services / `services.msc`），清單裡應該看得到「RedRockPrintAgent」且狀態是「執行中」；或直接開瀏覽器打 `http://localhost:3399/status` 確認有回應。

要移除服務、改回做法 A，一樣用系統管理員身分開命令提示字元，跑：
```
npm run uninstall-service
```

### 如果卡住了
- **裝置管理員完全看不到 COM 埠**：需要 admin 裝驅動程式，見第一步的說明。
- **`install.bat` 顯示「找不到 Node.js」**：確認 `nodejs-portable` 資料夾有跟 `install.bat` 放在同一層、且裡面真的看得到 `node.exe`。
- **`start.bat` 跳出來又馬上關掉／印表機沒反應**：把黑色視窗裡顯示的錯誤訊息截圖回報。
- **雙擊 `.bat` 檔完全沒反應／被記事本打開**：多半是 Windows 把副檔名藏起來了，實際檔名變成 `install.bat.txt`。改用命令提示字元直接輸入 `install.bat` 執行最準——如果出現「不是內部或外部命令」，就先用 `dir` 看真實檔名，抓到多餘的 `.txt` 就用 `ren "install.bat.txt" "install.bat"` 改回來。
- **`npm run install-service` 顯示錯誤**：幾乎都是**沒有用系統管理員身分**開命令提示字元/PowerShell——關掉重開一個，記得右鍵選「以系統管理員身分執行」再重試。

## ✅ 已實機驗證（2026-08-12，`DLE EOT` 狀態查詢，含開電＋紙張定位兩項）

`server.js` 用 `DLE EOT n`（`0x10 0x04 n`，ESC/POS 家族的即時狀態查詢指令）：

- **`n=1`（開電偵測）**：對應 `/status` 的 `connected`。**已完整實機驗證**：關電時無回應
  （`connected:false`）、開電後正確回應（`connected:true`）。
- **`n=4`（紙張定位偵測）**：對應 `/status` 的 `positionOk`／`journalMarkOk`（存根聯）／`receiptMarkOk`
  （收執聯）。**已於 2026-08-12 完整實機驗證通過，四輪讀數彼此自洽**：

  | 測試狀態 | 原始位元組 | bit5（存根聯） | bit6（收執聯） |
  |---|---|---|---|
  | 兩聯皆未定位（第1次） | `0x12` | 0 | 0 |
  | 兩聯皆定位成功 | `0x72` | 1 | 1 |
  | 只有收執聯未定位（存根聯仍正常） | `0x32` | 1 | 0 |
  | 兩聯皆未定位（第2次，重現） | `0x12` | 0 | 0 |

  精準對應到「哪一聯出問題哪一個位元才變」，且重複測試結果一致，非巧合。

  ⚠️ **極性跟同廠牌同系列機型 WP-520 官方操作手冊（附錄 B-2，已存於
  `docs/vendor-refs/WP-520-manual-same-family-as-WP-560.pdf`）記載的相反**——手冊寫「0=偵測到黑點
  (正常)、1=未偵測到(異常)」，但這台實機是反過來的「**1=偵測到黑點(正常)、0=未偵測到(異常)**」。
  `parsePaperSensorByte()` 已依實測結果校正極性（bit 位置沿用手冊：bit5=存根聯／bit6=收執聯，
  只有 0/1 的意義相反）。

  **一度誤判為不可用**：第一輪測試時比較的是「HTTP 端點解析後的布林值」對「後來單獨腳本抓的原始
  位元組」，沒有做到真正同條件的原始位元組直接對照，一度誤以為 n=2/3/4 三個查詢回傳同一個固定值、
  完全不隨紙張狀態變化——後來改用同一支診斷腳本在同一次連續測試中直接比較「未定位」與「定位成功」
  兩種狀態各自的原始位元組，才發現值真的有變、只是極性相反。**教訓：驗證「訊號是否隨狀態變化」
  務必用同一套方法、同一輪測試直接前後對照原始資料，不要拿不同測試方法/不同時間點的結果互相比較。**

`/print` 列印前會先查一次紙張定位狀態，偵測到 `positionOk:false` 直接拒絕列印並回錯誤訊息；查詢
無回應（可能斷線）一律放行，交由印表機自己既有的 `0x0C` 自動對位機制處理（已於 2026-07-31 驗證）。

## API

- `GET /status` → `{ connected, port, baud }`
- `POST /print` → body `{ gymId, items:[{name,qty,price}], total?, date?, buyerTaxId?, openDrawer? }`
  → `{ ok: true }` 或 `{ ok: false, error }`
- `POST /open-drawer`（獨立開櫃，不夾帶列印）→ `{ ok: true }` 或 `{ ok: false, error }`

號碼由 RedRock 後端管理，這支代理**不處理發票號碼/金額邏輯**，純粹「收到內容就印」。
